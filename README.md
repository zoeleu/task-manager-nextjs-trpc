# Task Manager

[Leia em português](README.pt-BR.md)

A simple task manager built with Next.js and tRPC. Tasks are kept in memory on the server and exposed through a tRPC API.

## Running it

Requires [Bun](https://bun.sh) (the repo pins `bun@1.4.4`). npm, pnpm and yarn should also work.

```bash
bun install
bun dev
```

Then open [http://localhost:3000](http://localhost:3000).

Run checks with `bun test`, `bun run lint`, and `bunx --no-install tsc --noEmit`.

For a production build: `bun run build && bun start`.

> Tasks live in memory, so they are lost whenever the server restarts.

## How it works

```
app/
  page.tsx                 Task list (server-rendered)
  tarefas/[id]/page.tsx      Create (/tarefas/nova) and edit (/tarefas/<id>) form
  api/trpc/[trpc]/route.ts tRPC HTTP endpoint
componentes/
  Tarefas.tsx                Fetches the first page on the server
  TarefasInfinitas.tsx        Loads subsequent pages on scroll
  Tarefa.tsx                 One row: complete, edit, delete
  FormularioTarefa.tsx             Shared create/edit form
lib/schema-tarefa.ts         Zod schemas, shared by client and server
servidor/armazenamento.ts            In-memory store (a Map)
trpc/                      tRPC setup: router, context, client and server helpers
```

### tRPC API

All procedures live in `trpc/roteadores/aplicacao.ts`.

| Procedure    | Type     | Input                                      | Errors                           |
| ------------ | -------- | ------------------------------------------ | -------------------------------- |
| `listarTarefas`  | query    | `{ limite?, cursor? }` → `{ itens, proximoCursor }` | `BAD_REQUEST`                 |
| `obterTarefa`    | query    | `{ id }`                                   | `NOT_FOUND`                      |
| `criarTarefa` | mutation | `{ titulo, descricao? }`                  | `BAD_REQUEST` (e.g. empty title) |
| `atualizarTarefa` | mutation | `{ id, titulo?, descricao?, concluida? }` | `NOT_FOUND`, `BAD_REQUEST`       |
| `excluirTarefa` | mutation | `{ id }`                                   | `NOT_FOUND`                      |

A task has an `id` (UUIDv7, generated by the server), a `titulo` (1–80 chars, required), an optional `descricao` (up to 300 chars), `dataCriacao` and `concluida`.

## Implementation decisions

- **The list is server-side rendered.** `componentes/Tarefas.tsx` calls the router on the server through `chamador` (no HTTP round trip) and streams in behind a `<Suspense>` spinner. The first 30 tasks seed an infinite query; an IntersectionObserver loads subsequent pages when the list ends within 1vh of the viewport bottom (recalculated on resize), with a manual button and retry feedback. UUIDv7 cursor pagination continues even when a boundary task is deleted.
- **One schema for client and server.** `lib/schema-tarefa.ts` is used by tRPC to validate requests and by the form before sending, so the two can't drift apart.
- **Create and edit share one page and one form.** `/tarefas/nova` for creation, and `/tarefas/<id>` for editing.
- **Feedback.** Validation errors appear under each form field, and server errors at the top of the form. Deleting announces success above the list. Mutations invalidate the paginated query so loaded pages stay in sync. Failed deletes and updates show an error under the task.
- **superjson** is used as the tRPC transformer, so `Date` values (like `dataCriacao`) survive the trip between server and client.
- **The store is kept on `globalThis`** so it isn't wiped every time the dev server hot-reloads a module.

## Notes

- **Next.js 16.** The brief mentions both Next.js 15 and "the latest versions"; this uses the latest (16.4.3).
- **Portuguese codebase.** Domain fields, components and tRPC procedures use Portuguese names. Framework and library contracts keep their original names. Routes use `/tarefas/nova` and `/tarefas/<id>`.
- **Not implemented:** authentication.
